Foundations

Flight Modes & Enforcement Levels

Highbeam separates what it observes from how forcefully it intervenes. A three-layer enforcement hierarchy lets you tune interruption policy from silent local telemetry to automated KV-cache and hysteresis gating without disabling Ring-0 security invariants.

1. The Three-Layer Enforcement Hierarchy

Every hook event (PreInvocation, PreToolUse, PreModelSwitch, and PostToolUse) is evaluated deterministically in sub-millisecond local JavaScript inside horizonConfig.mjs, circuitBreakers.mjs, cacheGravityRouter.mjs, and pre_invocation.mjs with zero LLM judge calls.

When computing an actionable decision (allow, non-blocking advisory warn, interactive ask, or hard deny), Highbeam resolves configuration layers in strict precedence from highest to lowest authority:

  1. Runtime Control Latch (~/.ctxtop/runtime/<sessionId>.ctl): Live operator states (PAUSED, STEP, or ABORTED) intercept execution immediately before policy rules run.
  2. Per-Detector & Habit Overrides (detectors and semanticDetectors): Project-local <workspace>/.attention-horizon.json overrides user-global ~/.attention-horizon/config.json. Explicit "off", "warn", or "block" settings supersede the active Flight Mode while Ring-0 security invariants remain protected.
  3. Top-Level Flight Mode & Host Router Level: Resolved from flightMode (OFF, SILENT, COACH, AUTO_PILOT) in .attention-horizon.json, V8 Mod state (ah_flight_mode), or daemon POST /api/router/mode, paired on Google Antigravity with hook_level (guard, advisory, off) in default_flightcheck.json and one-turn prompt prefixes (!, !force, !lock, #check).
  4. Catalog Default Posture (DETECTOR_CATALOG): Built-in per-detector classification as either a blocking guard circuit breaker or a non-blocking advisory hint.

2. The Four Flight Modes (OFF, SILENT, COACH, AUTO_PILOT)

Highbeam normalizes flightMode case-, hyphen-, and space-insensitively inside normalizeConfiguredFlightMode() (horizonConfig.mjs) and normalizeFlightMode() (circuitBreakers.mjs). Accepted aliases resolve cleanly: DISABLED maps to OFF, QUIET and MUTE map to SILENT, and AUTOPILOT and AUTO map to AUTO_PILOT. Unrecognized strings fall back safely to COACH.

Pro Entitlement Verification & Graceful Fallback

In hooks/handlers/pre-tool-use.mjs, selecting flightMode: "AUTO_PILOT" checks requireProFeature("auto_pilot_locks") against your offline Ed25519 license (~/.ctxtop/license.json) or active 14-day local trial (npx ctxtop pro trial). If no active entitlement is found, Highbeam automatically downgrades effectiveMode to "COACH" in memory so hooks never crash or lock you out of your editor.

3. AUTO_PILOT Escalations & Hysteresis Lock

Implemented in src/core-isomorphic/coach/cacheGravityRouter.mjs, AUTO_PILOT adds three stateful automation safeguards beyond static single-turn rules:

  • Hysteresis Lock (HysteresisLock): When DET-04 (3 consecutive tool failures) or DET-05 (edit thrashing) trips inside a debugging loop, AUTO_PILOT pins the active frontier model and elevates effort to "high" across subsequent turns. This stops an agent from prematurely downshifting to a smaller model before a fix is verified. The lock clears automatically when completeActiveTask() succeeds or resetOnRewindOrBranch() detects a conversation rewind/fork, or manually via POST http://127.0.0.1:62935/api/router/unlock-hysteresis.
  • Post-Compact Mutation Queue (PostCompactMutationQueue): Mid-session changes to effort, thinking, speed, system_prompt, mcp_tools, or model invalidate cached prompt prefixes when ttlRemainingSec > 0 and cachedTokens >= C*. In AUTO_PILOT, Highbeam queues those parameter shifts and flushes them safely immediately after /compact (PostCompact) or once the 5-minute (300s) TTL expires.
  • 3rd-Read AST Signature Stubs & Delta Diffs: When an agent attempts to re-read an entire source file a third time in the same session, foldCodeToSignatureStub() and computeCompactLineDiff() replace redundant payloads with compact symbol signatures or line deltas since the last read.
Example · Opus 4.7 -> Sonnet 4.6 Switch with 64,000 Warm Cached Tokens (C* = 26,667)
# In COACH mode (non-blocking advisory):
verdict: {
  decision: "allow",
  advisory: true,
  detectorId: "DET-08",
  cStar: 26667,
  cachedTokens: 64000,
  message: "[DET-08 Warm KV-Cache Hold] Prefix (64k > C* 26.7k) is warm ($0.50/MTok reads vs $3.75/MTok cold write). Delegate read-only lookup to Explore subagent on claude-haiku-5-5 (<2k context, 12-turn / 40k-token cap)."
}

# In AUTO_PILOT mode (active pre-switch gate):
verdict: {
  decision: "deny",
  blocked: true,
  detectorId: "DET-08",
  reason: "Mid-TTL switch blocked because cachedTokens (64,000) > C* (26,667). Wait for TTL expiry or run /compact."
}

4. Antigravity Router Levels (hook_level), Cooldowns & Chat Prefixes

On Google Antigravity, Highbeam evaluates user prompts in PreInvocation (src/hooks/pre_invocation.mjs) using settings merged from config/default_flightcheck.json and ~/.gemini/flightcheck/config.json. The hook_level key governs how router states behave:

hook_level Router Behavior 3-Turn Cooldown (halt_cooldown_turns: 3)
"guard" Default Halts vague or hazardous prompts with the 4-Line Scorecard (Context Health, Cache Window, Risk Signal, Recommended Action). After halting for a specific router state key, repeats of that same state within 3 turns automatically downgrade to a non-blocking { systemMessage } to eliminate nag loops.
"advisory" Never halts prompt submission. Every triggered router state injects { systemMessage } silently as advisory guidance. Downgrade is permanent until switched back to "guard" (or overridden by flightMode: "AUTO_PILOT").
"off" Skips Antigravity PreInvocation scoring while PreToolUse Ring-0 security breakers remain active. Not applicable.

Cooldown Exemptions (Physical Context & Billing Crises)

Three physical crises carry exemptFromCooldown: true and always fire immediately in "guard" mode even inside the 3-turn cooldown window:

  1. Context Truncation Crisis (amputationCrisis): Active context exceeds 140,000 tokens, placing Turn-0 architectural rules in AGENTS.md at risk of server-side FIFO truncation.
  2. Unconditional Warm Prefix Loss (DET-08): Destructive mid-TTL switch boundary where rebuilding cache costs more tokens than continuing.
  3. Haiku 100k 5x Pricing Cliff (DET-12): Haiku session crosses the 100,000-token pricing cliff.

In-Chat One-Turn Prompt Prefixes

Prefix Scope Behavior
! <prompt> or !force <prompt> Current turn only Bypasses the PreInvocation scorecard halt (ALLOW_SILENT). Ring-0 PreToolUse security guards stay armed.
!lock <prompt> Active task / session Pins the active model and effort posture alongside your prompt so background routing does not downshift mid-stream.
#check <prompt> Current turn only Forces a full Tier-2 diagnostic scorecard evaluation even if context metrics appear green.

5. Per-Detector & Habit Overrides (default | off | warn | block)

When global Flight Modes are too coarse, applyDetectorOverride() in src/core-isomorphic/config/horizonConfig.mjs lets you tune individual canonical detectors (DET-01..DET-20) and all 8 semantic habit slugs (formatter-bypass, drip-feed, vague-prompt-rubric, effort-overkill, post-commit-handoff, vision-screenshot-coach, micro-skills, relay-breaker):

  • "default": Inherits the detector's catalog posture (guard or advisory) and active flightMode behavior.
  • "off": Suppresses the rule (triggered: false, decision: "allow", overriddenByConfig: "off").
  • "warn": Downgrades a blocking detector to a non-blocking advisory (decision: "allow", blocked: false, advisory: true), prefixing [Advisory Override (DET-XX=warn)].
  • "block": Upgrades any advisory detector or habit slug into a hard pre-execution block (decision: "deny", blocked: true, advisory: false).

Surgical Profiles: Explicit Overrides Survive SILENT and OFF

Inside isCoachAdvisorySuppressed() (circuitBreakers.mjs), SILENT and OFF suppress detectors set to "default", but any detector or semantic habit explicitly set to "warn" or "block" in .attention-horizon.json still executes. This lets teams run zero-noise SILENT telemetry while strictly blocking specific expensive habits like cold-cache model switches.

Terminal · Surgical SILENT Profile + Strict FinOps Overrides
# Quiet all default chat coaching while strictly blocking cold-cache switches:
npx ctxtop config set DET-08 block
npx ctxtop config set vague-prompt-rubric warn
npx ctxtop config show --json

# Revert all custom per-detector overrides back to "default":
npx ctxtop config reset

6. Switching Modes Across Surfaces

Switch Flight Modes or router levels statically in JSON config files, interactively via CLI/V8 Mods, or live over the loopback daemon API.

<workspace>/.attention-horizon.json (or ~/.attention-horizon/config.json)
{
  "schemaVersion": "1.0.0",
  "flightMode": "COACH",
  "detectors": {
    "DET-08": "block"
  },
  "semanticDetectors": {
    "drip-feed": "warn",
    "vague-prompt-rubric": "default"
  }
}

Inside Claude Code with the Tier-1 V8 Mod active, run /horizon to inspect ah_flight_mode, or manage per-detector rules directly with npx ctxtop config set <ID|slug> <default|off|warn|block>. See the full config schema for all threshold keys.

~/.gemini/flightcheck/config.json
{
  "hook_level": "guard",
  "halt_cooldown_turns": 3,
  "warm_cache_lock_tokens": 50000,
  "cache_amputation_tokens": 140000
}

Setting flightMode: "AUTO_PILOT" in .attention-horizon.json overrides "hook_level": "advisory" to "guard" automatically. You can also toggle Flight Modes directly inside the Antigravity WebView HUD at http://127.0.0.1:62935.

Terminal · Loopback Daemon Runtime Control (127.0.0.1:62935)
# Switch live daemon router Flight Mode without restarting sessions:
curl -X POST http://127.0.0.1:62935/api/router/mode \
  -H "Content-Type: application/json" \
  -d '{"mode":"SILENT"}'
# Response: {"ok":true,"flightMode":"SILENT"}

# Manually release an active HysteresisLock triggered by DET-04 or DET-05:
curl -X POST http://127.0.0.1:62935/api/router/unlock-hysteresis
# Response: {"ok":true,"hysteresisUnlocked":true}

All loopback endpoints bind strictly to 127.0.0.1 with zero outbound network access. See MCP, HTTP Daemon & Micro-IPC for the full 28-route specification.
