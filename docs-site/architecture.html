System Architecture & Internals

Highbeam uses a six-package monorepo with zero npm dependencies. It keeps pure ESM context math cleanly separated from Node.js storage code and host plugins.

1. Six-Package Workspace Topology

Root package.json defines six packages under packages/* backed by shared code in src/core-isomorphic/, src/engine-node/, and src/core/:

Workspace Package Runtime Constraint Core Modules
@ctxtop/core Pure ESM, zero node:* imports DET-01..DET-32 rules, CircuitBreakerEngine, cacheGravity, dualTtl, cliffBreaker, horizonGrid, costRadarSvg, modViews, USTF v1 parser.
@ctxtop/engine-node Node.js >= 20.0.0 stdlib only node:sqlite read-only reader + JSONL offset fallback, Micro-IPC server/client, FTS5 log archiver, git merge-tree conflict check.

Decoupled Sister SKU: Highbeam Airlock (packages/airlock / ctxvault v1.0)

Local secret and PII scrubbing lives in the separate packages/airlock/ package (ctxvault v1.0, tested via npm run test:airlock). Keeping Airlock separate lets ctxtop stay focused on context health, KV-cache routing, and token savings.

2. Claude Mod Laws 1-5 & Pure-JS Cryptography

Claude Code's in-process module (not loaded by current versions) would run inside a sandboxed V8 isolate without Node.js built-ins, so every file in src/core-isomorphic/ follows five strict rules checked by test/mod_static_compliance.test.mjs:

  1. Zero node:* Imports: No node:fs, node:path, node:crypto, or node:child_process imports anywhere in core.
  2. Zero Unguarded Node Globals: Never touches bare Buffer or process without safe globalThis checks.
  3. Zero External npm Dependencies: No supply-chain risk and no bundler step needed.
  4. Pure JS Hashing: Uses pure-JS 64-bit FNV-1a (fnv1a64.mjs) for fast fingerprints and pure-JS SHA-256 (sha256HexPure) for checksums and receipts.
  5. Fast Rule Engine: evaluatePreToolUse and computeBreakEven run in about 0.2ms p95 inside the process. Each hook call also pays Node startup, so end-to-end it is ~60-80ms on Linux and ~200-275ms on Windows.

3. Lossless FTS5 CLI Output Compressor

Test runs and package installs often dump 50,000+ chars of progress bars and passing test lines. Built into src/core/fts5_output_compressor.mjs and src/shims/agy_cli_compressor.mjs (DET-07), the compressor cleans shell output in four steps:

  1. ANSI & Spinner Cleanup: Strips color codes and folds \r spinner lines before checking the 4,096-char size limit.
  2. Smart Noise Filters: Trims boilerplate from cargo test, npm install, and test suites while keeping every failed assert, stack trace, and compiler error.
  3. SQLite FTS5 & Polyfill Archive: Saves the full raw log to .ctxtop/cache/artifacts/ah_<sha256>.txt and indexes every line in .ctxtop/cache/artifacts_fts5.db. If a Node 22 build lacks SQLITE_ENABLE_FTS5 (or CTXTOP_FORCE_FTS5_POLYFILL=1 is set), src/engine-node/db/probe.mjs wraps DatabaseSync with createFts5PolyfillClass(). That provides drop-in USING fts5(...) tables, MATCH, bm25(), and centered snippet() windows (evaluateFtsSnippet).
  4. Searchable Summary: Sends the model a short head/tail + error summary plus an exact agy-horizon log-search "<query>" command so no debug detail is ever lost.

5. USTF v1 & 3-Way SHA-256 Mirror Parity

  • USTF v1 (src/core-isomorphic/ustf/): Maps Antigravity SQLite/JSONL steps and Claude Code events into one shared log format (version: "1.0.0", sessionId, harness, modelId, usage: { uncached, cacheWrite5m, cacheWrite1h, cacheRead, output, thinking, costUSD }, events, spans).
  • Release & Mirror Sync: When core or WebView files change, run node scripts/sync_mirrors.mjs first. Then run node scripts/generate_checksums.mjs and node bin/ctxtop.mjs verify --json so root files and plugin copies stay byte-for-byte identical.
