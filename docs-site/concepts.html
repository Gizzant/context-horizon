Foundations

Core Concepts & Mental Model

Highbeam treats each AI coding chat as a bounded working memory shaped by model attention and cache pricing. Four core ideas explain every warning, score, and guard in the tool.

Why Highbeam Exists

Long coding chats start failing quietly well before they hit a 200k or 1M token limit. Three common problems hurt code quality and drive up costs:

  1. Middle-of-Prompt Memory Drop: Model recall follows a U-shaped curve. Rules at Turn 0 (Primacy) and your newest tool outputs (Recency) stay sharp. Files and notes buried in the middle of a long chat are easy for the model to miss.
  2. Repeat File Reads & Log Bloat: Agents often re-read unchanged files or pull in huge test logs. That clutter pushes your early project rules toward the top edge where providers drop old tokens (a Context Truncation Crisis).
  3. Cold Cache Rebuilds: Switching models mid-chat or editing AGENTS.md or CLAUDE.md while a prompt cache is warm breaks the cache prefix. Your next turn pays full 1.25x cache-write prices across the whole history.

The 40-Cell Horizon Bar & U-Shaped Recall

Highbeam splits your active context limit into 40 time-ordered cells. Instead of one raw token count, the 40-Cell Horizon Bar shows what is in memory and where each item sits on the U-shaped recall curve.

Dynamic 40-Cell Zoom Tiers

In Claude Code and shared UI views (src/core-isomorphic/ui/horizonGrid.mjs), the 40-cell bar scales across three zoom levels so both small and huge windows stay easy to read:

  • 100k Haiku Cliff Ceiling (2,500 tokens/cell): Used on claude-haiku-5-5 up to 100,000 input tokens so you can spot the 100k 5x price step early.
  • 200k Standard Horizon (5,000 tokens/cell): Default scale for normal coding chats up to 180,000 input tokens.
  • 1M Extended Context Auto-Zoom (25,000 tokens/cell): Switches on automatically when total_input_tokens > 180,000 on 1M-window models like gemini-4-carbon, gemini-4-argon, claude-opus-5-5, and claude-sonnet-5-5.

KV-Cache Physics & Break-Even Math (C* & C_max)

Dropping from a large model like claude-opus-5-5 to a smaller model like claude-sonnet-5-5 sounds cheaper for quick edits. When a big prompt cache is warm, that move often costs more. Switching models (or changing reasoning effort while the cache is live) resets the warm KV cache. The new model then pays full cache-write prices for your entire chat history.

Highbeam's Cache Gravity Router (DET-08 in src/core-isomorphic/coach/cacheGravityRouter.mjs) checks both single-turn break-even C* (rule_v1) and multi-turn horizon break-even C_max (rule_v2) before a switch happens:

Single-Turn Break-Even (C*) & Horizon-Aware Break-Even (C_max)
# Single-turn break-even (rule_v1)
C* = [ O * (P_out,curr - P_out,target) + Delta_uncached * (P_write,curr - P_write,target) ]
     / [ P_write,target - P_read,curr ]

# Horizon-aware break-even over H_post remaining turns and R API requests/turn (rule_v2)
C_max = [ O * (P_out,A - P_out,B) * (H_post + 1) ]
        / [ (P_write,B - P_read,A) - ((H_post + 1) * R - 1) * (P_read,A - P_read,B) ]
  • O: Expected output tokens per turn. On turns 1-4, Empirical Bayes blends live output length toward outputShrinkagePriorTokens (500 tokens; outputShrinkageMinTurns: 5). From turn 5 on, it uses your Stop-hook 10-turn median in cal_<sessionId>.json (or 1,500 if unset).
  • H_post & R: Expected turns left and API calls per turn after switching. Both blend toward local Claude Code history in ~/.attention-horizon/cache/ah_session_prior.json (or DEFAULT_RPT_SHRINKAGE_PRIOR = 2.0), capped by turnsUntilCompact and the 496-session EMPIRICAL_SESSION_API_CALL_PRIOR.
  • P_out, P_read, P_write: Output, warm cache-read, and cold cache-write (1.25x 5m or 2.0x 1h) prices per million tokens for the current (A) and target (B) models.
  • Payback & Unbounded C_max: Highbeam reports exact paybackWarmRequests, paybackTurns, and horizonNetSavingsUSD (hiding noisy dollar estimates before Turn 5). If the C_max bottom term is <= 0, warm-read savings on the cheaper model beat the cold-write hit over H_post turns (C_max = Infinity), so the switch goes right through. Tiny hits below minSwitchPenaltyUSD ($0.02) and unknown non-Anthropic models also pass without blocking.

Worked Engineering Example

Say you are on claude-opus-5-5 with 48,000 warm cached tokens and want to drop to claude-sonnet-5-5 for a quick edit (O = 1,500, Delta_uncached = 0). Single-turn catalog math gives C* = 6,522 tokens (and C* = 4,615 tokens from claude-opus-4-6 to claude-sonnet-4-6). If your chat is almost done (H_post < paybackTurns and 48,000 > C_max), Highbeam holds the switch until the cache cools or asks you to confirm. Moving up to a stronger model always has C* = 0 and is never blocked.

Dual-TTL Countdowns & The Haiku 100k Cliff

Two more cost guards run in the background at all times:

  • Dual-TTL Countdown (dualTtl.mjs): Watches both the 5-minute (300s) prompt-cache timer and the 1-hour (3,600s) billing block. The status bar turns amber at <= 45s, shows a keep-warm tip at <= 15s, saves the State Baton at T-10s, and suggests 1-hour caching if at least 3.1% of your breaks last 5 to 60 minutes.
  • Haiku 100k 5x Cliff Breaker (DET-12, cliffBreaker.mjs): Guards Haiku chats against the 100,000-token 5x price jump. Prompts under 90k pass quietly. At 90k-98k you get a soft compact tip, 98k-100k triggers a strong warning, and >= 100k stops the turn before billing spikes. Other models are exempt.

Conductor vs. Executor Division of Labor

Highbeam fits naturally across both Google Antigravity and Claude Code:

  • Google Antigravity as Visual Conductor: Great for system planning, live side-panel HUD review (127.0.0.1:62935), browser checks via /browser, multi-agent work via /swarm, and fast read-only repo lookups with Delegation Scout (@ah-flash-scout, capped under 200 tokens so your main chat stays lean).
  • Claude Code as Fast Terminal Executor: Great for terminal TDD loops, Git worktree slices, sub-millisecond in-process V8 Mod checks (hooks/register.js), and live one-line ah-statusline tracking in tmux or IDE terminals.

Both hosts share the same repo lock and log files. First, .agents/locks/active_scopes.json stops two agents from editing the same file at once (DET-20). Second, USTF v1 (~/.ctxtop/sessions/) stores logs from both tools in one format for ctxtop inspect and ctxtop postmortem.

Flight Modes & Enforcement Levels

Highbeam separates tracking from blocking with a Three-Layer Control Stack. Per-detector rules (default, off, warn, block) in .attention-horizon.json come first. Top-level Flight Modes (OFF, SILENT, COACH, AUTO_PILOT) sit next, alongside Antigravity's router hook_level (guard, advisory, off) in default_flightcheck.json.

Mode / Level Surface Runtime Behavior
OFF Claude Code & Isomorphic Mutes habit tips and cache switch holds. Ring-0 safety guards (DET-01, DET-02, DET-18, DET-19) and custom overrides stay on.
SILENT Claude Code & Isomorphic Tracks live stats, updates ah-statusline, and logs Saved Quota Ledger totals without adding chat coaching notes.
COACH Default Claude Code & Isomorphic Runs default guard blocks, shows short 1-line tips on advisory rules, and queues warm-cache rule edits in PostCompactMutationQueue.
AUTO_PILOT Pro Isomorphic & V8 Mod Turns on HysteresisLock, auto 3rd-read AST stubs and delta-reads, active C* switch holds, and Antigravity guard mode (falls back to COACH without a Pro key).
guard / advisory / off Antigravity hook_level Sets whether Antigravity's PreInvocation router stops turns with a 4-line scorecard (guard, with a 3-turn cooldown) or shows soft warnings (advisory). Context Truncation Crisis, DET-08, and DET-12 skip cooldowns.
