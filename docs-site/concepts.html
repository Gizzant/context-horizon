Foundations

Core Concepts & Mental Model

Highbeam treats an AI coding session as a bounded memory system governed by attention recall geometry and prompt-cache economics. Understanding four foundational mechanisms explains every warning, metric, and guardrail in the product.

Why Highbeam Exists

Long coding trajectories fail quietly long before they hit a nominal 200k or 1M context limit. Three compounding failure modes degrade agent reliability and inflate API spend:

  1. Middle-Window Recall Decay: Transformer attention follows a parabolic curve. System rules at Turn 0 (Primacy) and the most recent tool outputs (Recency) retain strong recall, whereas files and instructions buried in the middle of a session suffer severe recall drop-off.
  2. Duplicate-Read & Output Bloat: Agents routinely re-read unmodified files or ingest multi-megabyte test logs. Those stale payloads push early architectural constraints toward server-side prefix truncation (a Context Truncation Crisis).
  3. Cold-Cache Prefix Rebuilds: Switching models mid-session or editing AGENTS.md / CLAUDE.md while a prompt cache is warm invalidates cached prefix tokens, forcing a full 1.25x cache-write rebuild on the very next turn.

The 40-Cell Horizon Bar & U-Shaped Recall

Highbeam divides your active context ceiling into 40 discrete chronological cells. Rather than showing a single opaque token counter, the 40-Cell Horizon Bar reveals both what occupies your context window and where each item sits along the parabolic attention recall curve.

Dynamic 40-Cell Zoom Tiers

In Claude Code and isomorphic views (src/core-isomorphic/ui/horizonGrid.mjs), the 40-cell bar automatically scales across three operational zoom tiers so small and large windows remain readable:

  • 100k Haiku Cliff Ceiling (2,500 tokens/cell): Active when running claude-haiku-5-5 at or below 100,000 prompt tokens, giving high-resolution visibility before the 100k 5x price cliff.
  • 200k Standard Operational Horizon (5,000 tokens/cell): Default resolution for standard coding sessions up to 180,000 input tokens.
  • 1M Extended Context Auto-Zoom (25,000 tokens/cell): Engages automatically when total_input_tokens > 180,000 on 1M-capable models (such as gemini-4-carbon, gemini-4-argon, claude-opus-5-5, and claude-sonnet-5-5).

KV-Cache Physics & Algebraic Break-Even (C*)

Intuition suggests switching from a frontier model (such as claude-opus-5-5) to a smaller model (such as claude-sonnet-5-5) saves money on simple follow-up edits. When a large prompt cache is already warm, that intuition is often backwards: switching models invalidates the warm KV prefix and forces the target model to pay full cache-write rates across the entire conversation history.

Highbeam's Cache Gravity Router (DET-08, implemented in src/core-isomorphic/economics/cacheGravity.mjs) solves the exact closed-form break-even threshold C* before any switch occurs:

Algebraic Cross-Model Break-Even Equation (C*)
C* = [ O * (P_out,curr - P_out,target) + Delta_uncached * (P_write,curr - P_write,target) ]
     / [ P_write,target - P_read,curr ]
  • O: Expected output tokens for the turn (800 low, 1,500 medium default, 3,500 high, 6,000 max).
  • P_out,curr and P_out,target: Output token prices per million tokens for the current and candidate models.
  • P_read,curr: Warm cache-read rate of the current model (for example, $0.20/M on claude-opus-5-5).
  • P_write,target: Cold cache-write rate of the target model (for example, $2.50/M 5m write on claude-sonnet-5-5).

Worked Engineering Example

Suppose you are working on claude-opus-5-5 with 48,000 warm cached tokens and consider downshifting to claude-sonnet-5-5 for a standard medium-effort edit (O = 1,500, Delta_uncached = 0). Substituting the catalog rates yields C* = 6,522 tokens (and C* = 4,615 tokens for claude-opus-4-6 to claude-sonnet-4-6). Because 48,000 > 6,522, downshifting would waste money by rebuilding the prefix. Highbeam holds the switch until the cache expires naturally. Capability upshifts (moving to a stronger model) always have C* = 0 and are never blocked.

Dual-TTL Countdowns & The Haiku 100k Cliff

Two additional economic boundaries run continuously in the background:

  • Dual-TTL Countdown (dualTtl.mjs): Tracks both the 5-minute (300s) ephemeral prompt-cache window and the 1-hour (3,600s) rolling billing block. The status bar raises an amber warning at <= 45s, offers optional keep-alive guidance at <= 15s, snapshots the State Baton at T-10s, and recommends upgrading to 1-hour caching when at least 3.1% of your inter-turn pauses fall between 5 and 60 minutes.
  • Haiku 100k 5x Cliff Breaker (DET-12, cliffBreaker.mjs): Monitors Haiku sessions against the 100,000-token 5x pricing step. Prompts below 90k pass silently; 90k-98k emits an advisory compaction prompt; 98k-100k trips a hard warning; and >= 100k halts execution before billing spikes. Non-Haiku models are exempt.

Conductor vs. Executor Division of Labor

Highbeam supports two complementary ways of working across Google Antigravity and Claude Code:

  • Google Antigravity as Stateful Visual Conductor: Ideal for architectural planning, side-by-side WebView telemetry inspection (127.0.0.1:62935), browser verification via /browser, multi-agent board coordination via /swarm, and delegating fast read-only repository lookups to Delegation Scout (@ah-flash-scout, capped at <200 tokens so your main frontier prefix stays lean).
  • Claude Code as High-Velocity Terminal Executor: Ideal for terminal-native TDD loops, Git worktree implementation slices, sub-millisecond in-process V8 Mod gating (hooks/register.js), and live single-line ah-statusline monitoring inside tmux or IDE terminals.

Both hosts share the same workspace governance artifacts: .agents/locks/active_scopes.json prevents concurrent agents from editing the same file simultaneously (DET-20), and USTF v1 (~/.ctxtop/sessions/) normalizes trajectories from both surfaces for unified ctxtop inspect and ctxtop postmortem analysis.

Flight Modes & Enforcement Levels

Highbeam separates observation from intervention through a Three-Layer Enforcement Hierarchy: explicit per-detector overrides (default, off, warn, block) in .attention-horizon.json, top-level Flight Modes (OFF, SILENT, COACH, AUTO_PILOT), and Antigravity's router hook_level (guard, advisory, off) in default_flightcheck.json.

Mode / Level Surface Runtime Behavior
OFF Claude Code & Isomorphic Mutes habit coaching and economic switch holds while Ring-0 security guards (DET-01, DET-02, DET-18, DET-19) and explicit overrides stay active.
SILENT Claude Code & Isomorphic Collects live telemetry, updates ah-statusline, and records Saved Quota Ledger metrics without injecting default chat coaching banners.
COACH Default Claude Code & Isomorphic Enforces default guard detectors, emits actionable 1-line coaching hints on advisory rules, and stages warm-prefix edits in PostCompactMutationQueue.
AUTO_PILOT Pro Isomorphic & V8 Mod Activates HysteresisLock, automated 3rd-read AST signature stubs and delta-reads, active C* switch holds, and forces Antigravity hook_level to guard (falls back gracefully to COACH if unlicensed).
guard / advisory / off Antigravity hook_level Controls whether Antigravity's PreInvocation router halts with a 4-line scorecard (guard, with a 3-turn halt cooldown) or injects warn-only notices (advisory). Context Truncation Crisis, DET-08, and DET-12 bypass cooldowns.
