Tutorial 2: Parallel Delegation on Git Worktrees with Scope Locks

Goal: Run two coding agents in parallel across Git worktrees without overwriting shared files or introducing silent merge conflicts, verified via DET-20, DET-31, and Cost Radar.

Create an isolated Git worktree for Worker B

When delegating concurrent edits (equivalent to Antigravity's workspace: "share" mode), create a dedicated branch worktree so each agent compiles and tests independently:

Step 1 · Create Feature Worktree
git worktree add ../repo-auth-slice -b feat/auth-slice
git worktree list

Claim an explicit Scope Lock Lease for Worker A

Reserve src/core/pro_license.mjs for Worker A (`session-alpha`) using the scope_lock_claim MCP contract (or automatic PreToolUse lease registration), writing atomically to .agents/locks/active_scopes.json:

Step 2 · Claim Lease via @ctxtop/mcp JSON-RPC
$ printf '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"scope_lock_claim","arguments":{"sessionId":"session-alpha","agentId":"claude-code","paths":["src/core/pro_license.mjs"],"ttlSeconds":900}}}\n' | npx ctxtop-mcp

Verify DET-20 blocks conflicting edits from Worker B

If Worker B (`session-beta`) attempts to edit src/core/pro_license.mjs while `session-alpha` holds an active lease, DET-20 halts the write before disk mutation occurs and prints a `git worktree` isolation hint:

Step 3 · Expected PreToolUse Collision Block
[DET-20 Multi-Agent Scope Collision] Blocked write to src/core/pro_license.mjs:
Active lease held by session "session-alpha" (claude-code, expires in 884s).
Work on disjoint files or isolate via git worktree.

Audit worktree topology and merge safety with Cost Radar

While both worktrees are active, DET-31 runs read-only git merge-tree checks in memory to catch overlapping hunks before merge, and cost-radar visualizes the swarm topology:

Step 4 · Generate Swarm & Worktree Timeline

Tutorial 3: Auditing Failed Runs, Stepping Execution & Surgical Pruning

Goal: Pause a runaway loop, single-step the next tool call, diagnose duplicate-read bloat across recent sessions, and surgically prune stale tool payloads with an automatic backup.

Pause and single-step a live agent trajectory

When an agent begins thrashing on failing tests (and approaches the DET-04 3-strike consecutive failure breaker), pause it from a second terminal using the Runtime Control FSM:

Step 1 · Pause, Step Once, and Resume
# Suspend at the next PreToolUse boundary (writes ~/.ctxtop/runtime/default.ctl)
$ npx ctxtop control pause --session default
[Highbeam Control] State transitioned to PAUSED

# Allow exactly 1 tool call, then automatically return to PAUSED
$ npx ctxtop control step --session default
[Highbeam Control] State transitioned to STEP

# Resume normal execution once verified
$ npx ctxtop control resume --session default
[Highbeam Control] State transitioned to RUNNING

Inspect normalized USTF v1 spans and run a Forensic Postmortem

Export the latest trajectory call tree and scan your last 10 sessions for CONTEXT_ROT_DECAY or VERIFICATION_CHURN:

Step 2 · Trajectory Inspection & Postmortem
$ npx ctxtop inspect --last
[Highbeam Inspect] Session "default" (claude-code)
  Model: claude-sonnet-5-5 | Events: 24 | Spans: 11
  Tokens: 92,400 (Uncached: 11,200, Cache: 81,200)

$ npx ctxtop postmortem --last 10
[Highbeam Postmortem] Analyzed 10 sessions (1.42M active tokens)
  Clean Sessions: 7 | Churn: 2 | Rot: 1
  Report: session_analysis_report.md

Preview and execute offline Tool-Output Surgery

Always run --prune-tools --dry-run first to inspect how many uncached stale tool outputs can be trimmed, then run without --dry-run (which writes an atomic .bak transcript backup first):

Tutorial 4: Zero-Loss Compaction & Cross-Model Spec Relay

Goal: Compress a deep 135k-token session into a verified State Baton without triggering warm-cache penalties, and structure a bounded Cold Critic Packet for external review.

Check cache TTL before compacting

Compacting while 50k+ tokens are still warm inside a 5-minute TTL window throws away paid cache reads (HOLD_COMPACT). Check live status first:

Step 1 · Inspect TTL & Saved Quota
$ npx ctxtop receipt --simple

Generate and audit the State Baton (/handoff)

Run /handoff in chat or generate the baton from the CLI. Verify all five checklist gates: concrete Next Action verb + file target, in-progress file list, active Blockers, architectural Decisions, and clean git status --porcelain:

Step 2 · Distill Handoff Document
$ npx ctxtop doctor --handoff
  ✔ PASS  Handoff Distillation           Generated handoff document at docs/HANDOFF_2026-11-12.md

Execute parameterized /compact and flush TurnZeroGate

Once cache TTL reaches 00:00 (or when crossing amputation_token_threshold), copy the parameterized compaction prompt from #btnCompactPrimary in the HUD and submit it in chat. Any rule promotions queued in PrefixCacheShield / TurnZeroGate flush automatically during PostCompact without incurring an extra cache rebuild.

Triage multi-model architecture reviews with /relay

When reviewing a specification with a second frontier model, invoke /relay to classify external critique claims into S0 (Blocker), S1 (Major Flaw), T (Testable Runtime Question, settled with a <30-line local script), and Defer, committing accepted edits directly to disk rather than pasting multi-thousand-token rebuttals in chat.
