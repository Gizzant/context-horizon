MCP Server, HTTP Daemon & Micro-IPC API

Highbeam exposes three local-only programmatic transports: a zero-dependency MCP stdio server for external AI editors, a loopback HTTP/SSE server for the WebView HUD, and a sub-15ms Micro-IPC socket for warm hook dispatch.

1. MCP Stdio Server (@ctxtop/mcp)

Implemented in packages/mcp/src/server.mjs (binaries ah-mcp and ctxtop-mcp, protocol version 2024-11-05), the MCP server accepts both newline-delimited JSON-RPC 2.0 messages and LSP-style Content-Length: <bytes>\r\n\r\n framed payloads over stdin/stdout.

.cursor/mcp.json Registration
{
  "mcpServers": {
    "attention-horizon": {
      "command": "npx",
      "args": ["-y", "--package=ctxtop", "ctxtop-mcp"]
    }
  }
}

2. Loopback HTTP & SSE Daemon API

sidecars/horizon-daemon/server.mjs binds strictly to 127.0.0.1 on port 62935 (scanning up to 62945 if occupied) and rejects POST bodies exceeding 4,096 bytes with HTTP 400/413.

3. Micro-IPC Socket Protocol (@ctxtop/engine-node)

Defined in src/engine-node/ipc/protocol.mjs, client.mjs, and server.mjs, the Micro-IPC Bridge lets short-lived CLI hook processes delegate evaluation to a warm local daemon over a user-scoped Unix domain socket (POSIX) or Named Pipe (Windows, overridable via CTXTOP_IPC_PATH).

  • Limits: MAX_BUFFER_SIZE_BYTES = 10,485,760 (10 MB), DEFAULT_CONNECT_TIMEOUT_MS = 15, DEFAULT_REQUEST_TIMEOUT_MS = 500 (extended to 600,000ms when suspended in PAUSED control state).
  • Fail-Safe Fallback: If no warm IPC server answers within 15ms, hook handlers evaluate CircuitBreakerEngine and .ctl files directly in process with zero error noise.
  • Standard JSON-RPC 2.0 Error Codes: -32700 (PARSE_ERROR), -32600 (INVALID_REQUEST), -32601 (METHOD_NOT_FOUND), -32602 (INVALID_PARAMS), and -32603 (INTERNAL_ERROR).
