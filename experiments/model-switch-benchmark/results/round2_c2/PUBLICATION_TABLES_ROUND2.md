## Table 5b — Measured vs. Uncalibrated vs. Calibrated Switch Economics, `R` Estimator, Growth `g` & Payback (`Opus 4.6 -> Sonnet 4.6`, `5m` Cache Tier)

Following code audit refinements and follow-up calibration:
1. **Legacy Single-Turn Threshold Removed (`C_max` Is Horizon-Aware):** The legacy single-turn zero-penalty ratio `O*dPout/(Pwrite_B - Pread_A)` solves only for `0` post-switch turns (`462–1,258` tokens on this workload, which `L1` also exceeds) and has been removed from all publishable prose and user-facing runtime hook strings. Runtime hold text reports the horizon-aware limit `C_max = O*dPout*(H+1) / ((Pwrite_B - Pread_A) - ((H+1)*R - 1)*(Pread_A - Pread_B))` (`Infinity` / always allow whenever denominator `<= 0`).
2. **Payback in Post-Switch Warm Requests & `a / b` Rule of Thumb:** Payback is reported primarily in **post-switch warm requests** (`W`, with post-switch turns `T = W / R` in parentheses). Let `a = P_write,B - P_read,A` (`$3.25/1M` on `5m`, `$5.50/1M` on `1h` for Opus 4.6 -> Sonnet 4.6) and `b = P_read,A - P_read,B` (`$0.20/1M`). As cached context `C` grows large, total warm reads required converge to `~a / b` (**`16.25` warm requests** on `5m`, **`27.50` warm requests** on `1h`), **less the output-token credit** `O*(P_out,A - P_out,B) / (C*b)` and **less `R - 1` warm reads already occurring on Requests `2..R` of the switch turn**. Worked examples at `C = 50,000, O = 400, 5m` (`unit`-tested in `round2_c1_fixes.test.mjs`):
   - **`R = 1`:** `11.32` post-switch warm requests (`11.32` turns), `11.32` total warm reads;
   - **`R = 5`:** `10.97` post-switch warm requests (`2.19` turns), plus `4` switch-turn warm reads = `14.97` total warm reads;
   - **`R = 10`:** `6.59` post-switch warm requests (`0.66` turns), plus `9` switch-turn warm reads = `15.59` total warm reads.
3. **Rolling-Median Shrunk `R` Estimator (`R_prior = 2.0`, Agreement Reduction & `>= 3` Local Transcript Override):** `PreModelSwitch` takes a **10-turn rolling median of per-turn API requests** (`rawRollingMedianRequestsPerTurn`, `MIN_TRUSTED_RPT_TURNS = 5`) shrunk at `n < 5` toward `R_prior`:
   - **Placeholder Rationale (`R_prior = 2.0`, Not Empirical Evidence):** Replaces `1.0` with `2.0` (`1` tool round + `1` reply, provenance `placeholder_single_tool_round_rpt_prior_2.0_not_empirical_evidence`) as a cold-start placeholder rationale, not as empirical evidence.
   - **Agreement-Reduced Shrinkage (`effectiveMinTrustedTurns = 2.5`):** When `>= 2` trailing turns agree within `<= 25%` relative spread (`turnsAgree = true`), `MIN_TRUSTED_RPT_TURNS` halves (`w = 0.8` at `n = 2`), yielding **`R_est = 4.4`** on `TH_allow [5, 5]` (cold-start) and **`R_est = 2.0`** on `L1 [2, 2]`.
   - **Strict `>= 3` Local Transcript Override Excluding Current & Benchmark Sessions (`isRealHumanUserTranscriptEntry`):** Once **`>= 3` non-current, non-benchmark** local deduplicated Claude Code transcripts exist in `~/.claude/projects/**/*.jsonl` (excluding the active session ID/path, excluding benchmark/harness transcripts containing `Benchmark-Run-Salt:` or benchmark paths, and filtering `isMeta` / `<local-command-*>` / `<command-name>` rows), their median `requests/turn` overrides `R_prior` (while survival quantiles keep the `>= 5`-session threshold). The earlier `+$0.2897` ("within 10%") offline figure — which depended on seeding a 1-session temp directory with `TH_allow`'s own benchmark transcript and compounding `g = 2,538` at `n = 2` — is **withdrawn**.
   - **Impact of Slash-Command Parser Fix (`isRealHumanUserTranscriptEntry`) on Earlier Figures:** Auditing all `78` benchmark session `.jsonl` transcripts confirms **zero change** to any pre-switch `PreModelSwitch` hook input (`turnsCompleted`, `rollingMedianOutputTokens`, `rollingMedianRequestsPerTurn` at `T3` or `T24`), **zero change** to assistant `message.id` dedupe counts (`byMsgId.size` identical across all `78/78` files), **zero change** to `EMPIRICAL_SESSION_API_CALL_PRIOR` buckets (indexed by `apiCallsCompleted`), and **zero change** to any published Round-2 table or CSV cost/turn figure. Only post-hoc full-session human turn counts on the exact `14` Round-2 transcripts where mid-session `set_model` (`/model`) succeeded change by `-3` (removing the `3` synthetic `/model` local-command rows appended at the switch boundary: `33 -> 30` on `L1_off r01–r03`, `L2_off r01–r03`, `L1_rule_v2 r01–r03`, `L2_rule_v2 r01`, `L1_calibrated r01`; `15 -> 12` on `U1_rule_v1 r01`, `U1_off r01`, `TH_allow r01`), while the remaining `64/78` transcripts have `0` change.
4. **Early-Session Forecast Guard (`< 5` Observed Turns) & Capped Growth Term (`g`):** `Stop` tracks per-turn prompt growth (`rollingMedianPromptGrowthTokens` = rolling median of consecutive turn-end context deltas). To prevent early-turn tool bursts (`T1–T2` `Read` growth `g = 1,954` in `L1`) from compounding across long horizons (`+$0.6307` vs `+$0.1248` measured), **`PreModelSwitch` caps growth extrapolation to `g = 0` (`capped_early_session_no_extrapolation`) until `n >= 5` observed turns (`turnsCompleted >= 5`, `promptGrowthSampleSize >= 4`) and a stable regime (`rptTurnsAgree = true`)**, and **suppresses the net dollar figure in user-facing hook messages whenever `turnsCompleted < 5` (`netDollarDisplaySuppressed = true`)**, displaying payback in post-switch warm requests (and turns) only.
